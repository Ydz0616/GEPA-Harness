Candidate — 0b131d92 (gepa:1)

You are a codebase Q&A assistant. Answer questions about GitHub repository `openai/openai-agents-python` at the exact commit `17d994bd3045dae71acda676a4ef4762ed8ecd94`.

The question is provided in the triggering event under `input.question`. Use GitHub tools to search/read the repository at that exact commit; do not answer from memory or from the default branch. If recursive tree output exceeds limits, use code search to locate the symbol, then read the specific file at the exact commit to verify it.

Your final message must be ONLY one valid JSON object, with no Markdown fences, no prose before or after, and no trailing explanation:

{"answer": <answer>, "path": "<repository-relative file path>"}

Rules for the JSON:

- `path` must be the exact repository-relative path of the file containing the answer, e.g. `src/agents/retry.py`, not a GitHub URL, not an absolute path, and not a directory unless the answer truly is a directory.

- `answer` must be minimal and exact. Do not put a full explanatory sentence in `answer` when the expected answer is a list, scalar, value, or path.

- For questions asking to list fields/attributes/properties of a class, return a JSON array of exact member names in source order. Do not include types, defaults, constraints, descriptions, method names, or prose. Example: `ModelRetryBackoffSettings` is defined in `src/agents/retry.py`; its field-name answer is `["initial_delay", "max_delay", "multiplier", "jitter"]`. Do not answer “ModelRetryBackoffSettings has four fields: ...”.

- For questions asking the value of a constant/variable, return only the bare value as a JSON string, without the symbol name or assignment. Normalize numeric literals by removing underscore separators. Example: `DEFAULT_MAX_ARCHIVE_MEMBERS` is in `src/agents/run_config.py` and is written `100_000`; the answer should be `"100000"`, not `"DEFAULT_MAX_ARCHIVE_MEMBERS = 100_000"`.

- For questions asking where a class/function/symbol is defined or which file contains it, return the exact repository-relative path as the `answer` string, and put the same path in `path`. Example: `Handoff` is defined in `src/agents/handoffs/__init__.py`. Related classes such as `HandoffCallItem`, `HandoffOutputItem`, and `HandoffSpanData` are not the `Handoff` definition.

- For scalar answers, use a JSON string containing only the value. For multiple fields/values, use a JSON array. Keep backticks, markdown, source links, and explanatory text out of the `answer` field.

Use the code at the specified commit as the source of truth. Verify the file path and answer against the actual source before emitting the final JSON object.

What it learned, mapped to the baseline's failure modes.
  1. Final message = one JSON object, no fences, no prose → fixes "JSON wrapped in explanation".
  2. answer is the bare value / array / path → fixes "value with explanation in parentheses" (the biggest cause, 14 of 15 baseline misses).
  3. path is a repository-relative file, not a URL or directory.
  4. Read at the pinned commit, never from memory or the default branch; code-search first when the tree is too large.

It also wrote the three training facts into the prompt as examples (100_000 → "100000", Handoff lives in handoffs/__init__.py, the field list of ModelRetryBackoffSettings) — the "niche factual information" GEPA's meta-prompt asks for. These are procedural rules, not new reasoning.

When the question asks why Pint raises `OffsetUnitCalculusError` for statistical operations on offset units such as `degC`:

- `docs/nonmult.rst` (approximately lines 94–97) documents the ambiguity.
- Auto-converting variance to `delta_degC²` would silently reinterpret absolute readings as intervals. Pint instead refuses to guess and forces the user to convert to kelvin or work explicitly in delta units.
- Test coverage may be in `pint/testsuite/test_numpy_func.py` (approximately lines 172–173 for `get_op_output_unit("variance", ureg.degC)`).

**Answer — how Sanic parses HTTP/1.1 request headers** (`sanic-org/sanic` @ `57d44f2`)

The parser lives in `sanic/http/http1.py`, method `Http.http1_request_header()`. `Http` (a `Stream` subclass from `sanic/http/stream.py`, with `TouchUpMeta`) is driven by `sanic/server/protocols/http_protocol.py`: `data_received()` appends socket bytes to `recv_buffer` and the `http1()` loop calls the header parser for each request on the connection.

**1) Buffer scan, not a state machine.** It does not feed bytes to `h11`/`httptools`; it locates the head terminator directly:

```python
buf = self.recv_buffer
pos = 0
while True:
    pos = buf.find(b"\r\n\r\n", pos)
    if pos != -1: break
    pos = max(0, len(buf) - 3)          # keep 3 bytes overlap for a split terminator
    if pos >= self.HEADER_MAX_SIZE: break
    await self._receive_more()
if pos >= self.HEADER_MAX_SIZE:
    raise PayloadTooLarge("Request header exceeds the size limit")
```

The `len(buf) - 3` overlap is what makes a `\r\n\r\n` straddling two TCP reads safe. Sizing comes from `HEADER_CEILING = 16_384` (hard cap) and `HEADER_MAX_SIZE` (0 = unlimited until set), configured once at startup through `Http.set_header_max_size(*sizes)` → `min(*sizes, HEADER_CEILING)`.

**2) One decode, then plain string splits.**

```python
head = buf[:pos]
raw_headers = head.decode(errors="surrogateescape")   # lossless, never raises on bad bytes
reqline, *split_headers = raw_headers.split("\r\n")
method, self.url, protocol = reqline.split(" ")
```

`surrogateescape` means malformed octets survive instead of blowing up. The request line must be exactly three space-separated tokens — no tolerant/lenient parsing.

**3) Signal, then version → keep-alive default.** `await self.dispatch("http.lifecycle.read_head", inline=True, context={"head": bytes(head)})` exposes the raw head to listeners. Then `HTTP/1.1` → `keep_alive = True`, `HTTP/1.0` → `keep_alive = False`, anything else → a bare `raise Exception` (deliberately, so the outer handler turns it into a 400).

**4) Header loop — cheap and manual.**

```python
for name, value in (h.split(":", 1) for h in split_headers):
    name, value = h = name.lower(), value.lstrip()
    if name in ("content-length", "transfer-encoding"): request_body = True
    elif name == "connection": self.keep_alive = value.lower() == "keep-alive"
    headers.append(h)
```

Split on the *first* colon only (values with colons stay intact), lowercase the name (case-insensitive per RFC 7230), `lstrip` the value (also absorbs obs-fold continuation lines), and a `Connection` header overrides the version default. `headers` stays a flat `list[tuple]`. Any exception in the whole block is caught and re-raised as `BadRequest("Bad Request")`.

**5) Wrap, check upgrade, validate URL.** `headers_instance = Header(headers)` — `sanic/compat.py`, a `CIMultiDict` subclass giving `getone`/`getall` for duplicates. `upgrade_websocket = headers_instance.getone("upgrade", "").lower() == "websocket"`. Then `self.url.encode("ASCII")`, with `UnicodeEncodeError` → `BadRequest("URL may only contain US-ASCII characters.")` — the URL still raw bytes here.

**6) Construct the structured `Request`.**

```python
request = self.protocol.request_class(
    url_bytes=url_bytes, headers=headers_instance, head=bytes(head),
    version=protocol[5:],            # "HTTP/1.1" -> "1.1"
    method=method, transport=self.protocol.transport, app=self.protocol.app,
)
self.protocol.request_class._current.set(request)     # ContextVar
await self.dispatch("http.lifecycle.request", inline=True, context={"request": request})
```

Structured fields (`path`, `args`, `query_string`, `host`, `scheme`) are not built by the parser — `Request` keeps `raw_url`/`head` and derives them lazily via `parse_url` (`urllib.parse.urlsplit`).

**7) Body framing decided from the same headers.** With `Expect: 100-continue` → `expecting_continue = True` (anything else → `ExpectationFailed`); `Transfer-Encoding: chunked` → `request_body = "chunked"` and `pos -= 2` so one CRLF is *left* in the buffer for the chunk-size reader; otherwise `Content-Length` is `int()`-parsed into `request_bytes_left`.

**8) Hand off.** `del buf[:pos + 4]` drops head + terminator; `self.request, request.stream = request, self` links the request back to the `Http` object so `await request.read()` / async iteration flows through `Http.read()` (chunk parsing, size limits, `http.lifecycle.read_body`); `requests_count` is incremented. `http1()` then moves to `Stage.HANDLER` and calls `protocol.request_handler(request)`.

Worth noting: this function is listed in `Http.__touchup__`, i.e. Sanic's `touchup` source-rewriting generates specialised variants and picks the fastest at class creation — the straightforward code above is the reference implementation. On any parse failure the connection switches to an empty `Request` (`create_empty_request`) so error handlers still have an object to work with.

**Short answer:** Sanic does not use a streaming HTTP state machine for the request head. `Http.http1_request_header()` in `sanic/http/http1.py` accumulates socket bytes into the connection's `recv_buffer`, finds the `\r\n\r\n` terminator with `bytes.find`, decodes the whole head at once with `surrogateescape`, splits it manually into a request line and header lines, builds a case-insensitive `Header` multidict, and hands those pieces to `Request(...)` — where `httptools.parse_url` finishes the job into a structured `Request`.

## The pipeline, in execution order

**1. Entry loop — `Http.http1()`** (class `Http(Stream, metaclass=TouchUpMeta)`). While `self.keep_alive and self.stage is Stage.IDLE`: `init_for_request()`, wait for bytes if `recv_buffer` is empty, set `Stage.REQUEST`, arm `self.response_func = self.http1_response_header`, then `await self.http1_request_header()`. `self.recv_buffer` is the protocol's buffer (`self.recv_buffer = protocol.recv_buffer` in `__init__`) — a single `bytearray` appended to by `data_received`, not a per-request copy.

**2. Framing the head — terminator scan**

```python
buf = self.recv_buffer
pos = 0
while True:
    pos = buf.find(b"\r\n\r\n", pos)
    if pos != -1:
        break
    pos = max(0, len(buf) - 3)
    if pos >= self.HEADER_MAX_SIZE:
        break
    await self._receive_more()

if pos >= self.HEADER_MAX_SIZE:
    raise PayloadTooLarge("Request header exceeds the size limit")
```

`pos` is reused for two jobs: search start, then the index of the CRLFCRLF. Restarting the scan at `len(buf) - 3` is the important trick — no byte is rescanned after each socket read, and 3 is the exact window in which a *split* delimiter can hide (`\r\n\r` / `\r\n` / `\r` arriving in the next packet). Because the loop breaks on the size check before `find` succeeds, an oversized head cannot be "completed" by luck.

`HEADER_MAX_SIZE` is a **class** attribute (`HEADER_MAX_SIZE = 0`, `HEADER_CEILING = 16_384`), set through `Http.set_header_max_size(*sizes)` → `min(*sizes, cls.HEADER_CEILING)`. The ceiling is hard: no configuration can raise the request-head cap above 16 KiB.

**3. Head → text → lines**

```python
head = buf[:pos]
raw_headers = head.decode(errors="surrogateescape")
reqline, *split_headers = raw_headers.split("\r\n")
method, self.url, protocol = reqline.split(" ")
```

- `head` excludes the terminating `\r\n\r\n` (so `Request.head` is the head *without* the blank line).
- `surrogateescape` is deliberate: latin-1/raw bytes in a header survive the decode instead of raising `UnicodeDecodeError`.
- `reqline.split(" ")` must yield exactly 3 fields — a request target containing a space, or a malformed line, raises `ValueError` and is caught below as a 400.

**4. Early hook — `http.lifecycle.read_head`.** Before any header is interpreted, the raw bytes are dispatched:

```python
await self.dispatch("http.lifecycle.read_head", inline=True, context={"head": bytes(head)})
```

This is the point at which middleware/listeners can see the untouched head (useful for rejecting a request before `Request` exists). `inline=True` matters because the class declares `__touchup__ = ("http1_request_header", "http1_response_header", "read")` with `TouchUpMeta` — Sanic's touchup service rewrites these hot methods at class-creation time so the dispatch is inlined.

**5. Version → keep-alive, then header folding**

```python
if protocol == "HTTP/1.1":
    self.keep_alive = True
elif protocol == "HTTP/1.0":
    self.keep_alive = False
else:
    raise Exception  # Raise a Bad Request on try-except

self.head_only = method.upper() == "HEAD"
request_body = False
headers = []

for name, value in (h.split(":", 1) for h in split_headers):
    name, value = h = name.lower(), value.lstrip()

    if name in ("content-length", "transfer-encoding"):
        request_body = True
    elif name == "connection":
        self.keep_alive = value.lower() == "keep-alive"

    headers.append(h)
```

Semantics worth naming:

- `split(":", 1)` — only the first colon separates name from value, so `Location: https://…`, absolute-form targets, and `Date` values parse correctly.
- `name.lower()` normalizes keys; `value.lstrip()` strips leading OWS only. Trailing OWS stays part of the value (a difference from httptools' stricter trimming).
- No obs-fold support: a folded continuation line (leading space, no colon) raises `ValueError` → the whole block becomes `BadRequest("Bad Request")`.
- `connection` overrides the protocol default in either direction (`Connection: keep-alive` on HTTP/1.0, `Connection: close` on HTTP/1.1), evaluated after the version branch.
- `request_body` is a *flag only* — the presence of `content-length` or `transfer-encoding`, not its value, decides whether body handling is armed.
- `h` is intentionally kept as the `(name, value)` tuple, because that list is consumed by the multidict constructor next.
- The bare `raise Exception` is caught by the enclosing `except Exception: raise BadRequest("Bad Request")` — every parse failure in this block collapses into one opaque 400 without leaking the reason.

**6. List of tuples → structured, case-insensitive headers**

```python
headers_instance = Header(headers)
self.upgrade_websocket = (
    headers_instance.getone("upgrade", "").lower() == "websocket"
)
```

`Header` is `sanic.compat.Header` (a CIMultiDict-style multidict). It accepts an iterable of pairs, which is why step 5 produced tuples rather than a dict: duplicate headers (`Set-Cookie`, repeated `Cookie`, custom repeats) are preserved in insertion order and retrievable with `getone(...)`; lookups are case-insensitive, so the earlier lowercasing is a convenience, not a correctness requirement. WebSocket upgrade detection reads only the `upgrade` token here.

**7. Target encoding guard**

```python
try:
    url_bytes = self.url.encode("ASCII")
except UnicodeEncodeError:
    raise BadRequest("URL may only contain US-ASCII characters.")
```

Note the asymmetry: the *head* was decoded with `surrogateescape`, but the request target is re-encoded to strict ASCII. A non-ASCII path (raw UTF-8 in the request line) is therefore rejected — clients must percent-encode.

**8. Constructing the `Request`**

```python
request = self.protocol.request_class(
    url_bytes=url_bytes,
    headers=headers_instance,
    head=bytes(head),
    version=protocol[5:],          # "1.1" / "1.0"
    method=method,
    transport=self.protocol.transport,
    app=self.protocol.app,
)
self.protocol.request_class._current.set(request)
await self.dispatch("http.lifecycle.request", inline=True, context={"request": request})
```

`request_class` defaults to `sanic.request.Request` but is overridable per app, so this is where a custom request type enters. Inside `Request.__init__` (sanic/request/types.py) the object becomes *structured*:

- `self.raw_url = url_bytes`, then `self._parsed_url = httptools.parse_url(url_bytes)`; on `HttpParserInvalidURLError` it raises `BadURL(f"Bad URL: {url}")` (decoded with `backslashreplace` just for the message).
- `self.headers = Header(headers)` — headers are re-wrapped, so the instance the handler sees is a fresh multidict.
- `version`, `method`, `transport`, `head` stored; `body = b""`; `conn_info = None`; context and all parsed caches (`parsed_args`, `parsed_cookies`, `parsed_credentials`, `parsed_files`, `parsed_form`, `parsed_forwarded`, `parsed_json`, `parsed_token`, `parsed_accept`) start as `None`.
- Everything else is **lazy**: `path` and `query_string` decode `self._parsed_url.path/.query` (UTF-8); `get_args()`/`args` run `parse_qs` over `query_string` (memoized per `(keep_blank_values, strict_parsing, encoding, errors)`); `cookies` parse the `cookie` header; `forwarded` runs `parse_forwarded` then falls back to `parse_xforwarded`; `scheme` resolves `SERVER_NAME` → `forwarded["proto"]` → SSL; `host`/`server_name`/`server_port` come from `SERVER_NAME` → `forwarded` → the `host` header via `parse_host`. So header *bytes* become Python values only when the handler asks for them.
- `Request._current` (a `ContextVar`) is set, making `Request.get_current()` work from anywhere inside the lifecycle.

**9. Body framing decided from the head alone**

```python
self.request_bytes_left = self.request_bytes = 0
if request_body:
    headers = request.headers
    expect = headers.getone("expect", None)
    if expect is not None:
        if expect.lower() == "100-continue":
            self.expecting_continue = True
        else:
            raise ExpectationFailed(f"Unknown Expect: {expect}")

    if headers.getone("transfer-encoding", None) == "chunked":
        self.request_body = "chunked"
        pos -= 2  # One CRLF stays in buffer
    else:
        self.request_body = True
        self.request_bytes_left = self.request_bytes = int(headers["content-length"])

del buf[: pos + 4]
self.request, request.stream = request, self
self.protocol.state["requests_count"] += 1
```

- `Expect` is validated strictly: only `100-continue` (any case) is accepted; anything else is a `417` via `ExpectationFailed`.
- Chunked wins over `Content-Length` when both are present — no smuggling negotiation; chunked is chosen and the rest of the body is parsed incrementally in `read()`.
- `pos -= 2` is not a bug: it leaves the **second** CRLF in the buffer. `read()` then looks for the chunk-size terminator with `buf.find(b"\r\n", 3)` and parses `int(buf[2:pos].split(b";", 1)[0], 16)`, i.e. it expects the buffer to start with `\r\n<hex-size>[;ext]\r\n`. The retained CRLF is what makes that framing work.
- `del buf[: pos + 4]` mutates the shared buffer in place, so any pipelined next request stays queued (this is what allows keep-alive without a second socket read).
- `request.stream = self`: the `Request` itself is the body stream (`__aiter__`/`read()`), so `request.receive_body()` pulls bytes lazily; `Content-Length` accounting lives in `request_bytes_left`, the `REQUEST_MAX_SIZE` check (`raise PayloadTooLarge("Request body exceeds the size limit")`) happens per chunk in `read()`.
- Back in `http1()`, `request.conn_info = self.protocol.conn_info` is attached and `await self.protocol.request_handler(self.request)` runs — that is where routing/middleware take over.

## Design points and consequences

- **Hand-rolled scanning, not an incremental parser.** Sanic owns the byte loop (`find` in C, one decode, one split pass) and only borrows `httptools` for URL parsing inside `Request.__init__`. This keeps allocation low and gives Sanic full control of the `read_head` hook, at the cost of strictness: malformed header lines, oversize heads, and bad versions all degrade into a single `BadRequest("Bad Request")` with no diagnostic detail, and obs-fold is unsupported.
- **The head is bounded, the body is not buffered.** 16 KiB is the hard head ceiling; the body is streamed and capped separately by `REQUEST_MAX_SIZE`.
- **Header values are materialized twice** (`Header(headers)` in `http1.py`, then `Header(headers)` again inside `Request.__init__`) — cheap, but it means a `read_head` listener cannot mutate the dict the request ends up with; it would have to mutate `head` bytes.
- **One caveat visible in the code structure:** the `try/except Exception → BadRequest` covers only the request-line/version/header-folding section. The body-framing block that follows is outside it, so a `transfer-encoding` present without `content-length` and not equal to `chunked` hits `headers["content-length"]` and raises `KeyError`, which surfaces through `http1()`'s `except Exception` → `error_response` as a server error rather than a 400. If you need that to be a clean 4xx (or you rely on `Transfer-Encoding: gzip` being honoured), that is the line to guard.
- If you need different parsing (lenient folding, larger heads, extra normalisation), the supported levers are `Http.set_header_max_size(...)` (capped at 16 KiB), a custom `request_class`, and `read_head`/`request` lifecycle listeners — not subclassing the parser, because `http1_request_header` is a touchup-patched method.
